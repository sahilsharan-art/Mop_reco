# V2 (React) screens: audit against the Streamlit version, and what was changed (25 Nov 2026)

Two independent read-only reviews (API and screens) were run against the code merged as `6f26120`, with the Streamlit dashboard as the baseline; every finding below was read in the code, and the API ones were reproduced where marked. This page records what was FIXED in this change, what is still OPEN, and the speed measured. Server names and credentials are deliberately not written here.

## 1. Speed (full 01/04 - 14/11 run, 45,580 store-days, 5.6M bill lines, development PostgreSQL)

| Request | Before | After | How |
|---|---|---|---|
| Summary | 13.4 s | 4.6 s | the headline and the daily trend read the run's saved per-store-day results instead of counting every bill line; the digital-received figure is `digital_sale - unmatched + manual-only` instead of a SUM over every matched line; the store-day sheet loads as float tuples, not ORM objects |
| Cash (each page) | 4.5 s | 0.35 s | the sheet is built once per (run, period, store, manual-match state) and kept two minutes |
| Float (each page) | 5.2 s | 1.3 s | same |
| `load_fast` (used by the Streamlit Summary too) | 4.4 s | 0.7 s | same loader |
| Notices (new) | - | 2.4 s first, then cached one minute | |

The three engine changes are proved IDENTICAL to the originals, to the paisa: F on all 45,580 store-days, and the verdict and the daily trend for the whole run, each of the eight months, one day and five stores (`scripts/audit_fastpath_equivalence.py --run 2`; tests in `tests/test_v2_perf_fastpaths.py`). The original functions stay in the code as the reference.

## 2. Fixed in this change

| # | Finding | Fix |
|---|---|---|
| A1 P1 | **Warnings and controls were missing**: nothing told the user the POS file was cut off, a month was unreconciled, Axis was parked, a control failed or a bills/transactions MISMATCH existed | new `GET /notices` (`app/api_v2_notices.py`) reusing the old app's own logic; shown above every screen, loud only when something is wrong. Verified on the full run: it shows the cut-off November POS file (209,757 of 1,187,732 bill numbers) and control (d) FAILED (1,643 negative-closing store-days) |
| A2 P1 | A **split payment that does not add up to the bill could be recorded with an override** (reproduced: 60,000 + 30,000 against 100,000 stored; the 10,000 shortfall written off) | a split must be exact and clean (422 otherwise) and never accepts an override; test added |
| A3 P1 | Upload and bulk routes ran blocking work inside the async event loop, stalling every user's request (login included) for the length of one validation | both are plain `def` (thread pool) |
| A4 P1 | Bulk matching loaded the whole warehouse (4.4-5.6M rows) on every preview and confirm | looks up only the transactions the file names |
| A5 P1 | Exceptions: one blended value over bills, transactions and "neither" (CLAUDE.md 6.9a); closed items mixed into the working list; remarks invisible | default = open + under investigation (`all` to see history); `groups` return not-received and received-not-billed apart; the latest remark, who and when on every row |
| A6 | Period wholly outside the run returned zeros with no warning (6.24) | 409 "not reconciled" naming the run's range; partial overlap is announced by a notice |
| A7 | Unauthenticated callers got 409 on period-dependent routes (work before sign-in, and it revealed which runs exist) | sign-in is checked first (401) |
| A8 | `/bulk/refund_folder` always returned 500 | the uploaded workbook is read with the folder reader; a named 422 when it cannot be |
| A9 | The store filter did nothing on the CMS grid (column is `STORE NAME`) | fixed |
| A10 | Writes accepted any completed run from the browser | writes are pinned to the latest completed run (409 otherwise); reading an older run still works |
| A11 | Tasks: closed tasks in the default list, remarks accepted on a closed task | default = live tasks (`all` for closed); closed tasks take nothing more |
| A12 | Error responses lacked the security headers; a duplicate write was a 500; an unknown id surfaced raw | headers on every error; `IntegrityError` = 409, `LookupError` = 404 |
| A13 | 50 full run rows (1.4 MB of notes each) loaded for every request | notes are deferred |
| A14 | Exports: the header claimed a `search` that was not applied; the amount column lost its money format | only tasks claim a search; `value_column` set |
| B1 | Refetch every 60 s on every open screen, re-running the multi-second endpoints | no polling (two-minute freshness); only Runs polls (10 s) |
| B2 | Blank page for the whole load; one request per keystroke; page 7 of 2 after a filter change; header sort looked global | the previous result stays on screen while the next loads, a loading view, debounced search, page reset on filter change |
| B3 | Dates showed as ISO; counts were not Indian-grouped; gift voucher / credit notes printed raw | DD/MM/YYYY and Indian grouping in one formatter (ids are never touched) |
| B4 | A negative cash receivable was shown; page footers summed balances and mixed exception types | the screen floors cash receivable at 0 (exports stay signed); footers sum only flows, never on Exceptions |
| B5 | A blended "match rate" and a combined "open exceptions" tile | "Matched by system" with manual and asserted counts beside it; "Amount not received" only |
| B6 | Choosing another run kept the previous run's dates | dates are cleared (the run's own whole range); a notice appears when the run is not the latest |

Tests: `tests/test_v2_audit_fixes.py` (11), `tests/test_v2_perf_fastpaths.py` (11); the earlier 46 V2 tests and the related suites still pass (135 passed).

## 3. Still OPEN (needs a decision or more work; none hidden)

* **Float is stripped** (P2): no high-float flag, tiles, filters, remark history, bulk upload or the two Data-quality lists (negative float, Defect B). A store can hold a high float with no signal. Streamlit's Float page remains the reference.
* **Summary: no store cash card, no bills/transactions strip tables, no controls table, no store-wise detail with per-date expansion, no Matched list**. The warnings above now surface a FAILED control or MISMATCH; the full tables are not reproduced.
* **Exceptions**: one register, not two tables (bills / transactions); the Txn 1 / Txn 2 pairing columns are missing. Matching has no By-transaction direction, register export, batch-reverse button or date-lag list. Masters edit has no preview/diff before saving; Upload takes one file (Paytm arrives in parts) and posts it twice (preview, then confirm); Users has no sign-in trail; CMS lacks the bridge / credited-later / ZPO lists and has a NEW override feature that needs Finance sign-off (it overwrites a computed bank-credit figure; rules 3 and 5).
* **Logo**: the supplied CityKart MOP Reco logo is not in V2 (a "CK" tile). The page loads a Google font: self-host it if user PCs have no internet.
* `/store-sheet/export` runs the slow raw-file build inside the request (33 s, unlocked); `/matching` search is a full scan on 5.6M lines; `/float` has no server-side filters; `/cms` and several lists are sent whole and paged in the browser.
* Roles: any signed-in person can edit masters, run, restore and withdraw uploads (parity with Streamlit, section 6.40) - a role design is still needed.
* Not yet measured in production: HTTPS, the proxy, concurrent users. Keep the Streamlit dashboard until a finance user has accepted V2.
